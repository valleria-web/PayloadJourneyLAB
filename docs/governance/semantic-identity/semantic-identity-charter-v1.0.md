## 3. Institutional Description

Payload Journey LAB is an author-led laboratory for software system investigation, methodological research and technical education.

The LAB studies how operations move through software systems across representations, layers, decisions, states and effects, with particular attention to restoring structural understanding in increasingly complex and AI-accelerated codebases.

Its work combines conceptual modelling, payload tracing, evidence-based investigation, applied case studies and technical education.

The LAB develops and teaches methods including Payload Journey, USMT, Reverse Payload Journey, Operational Payload Path and Track to Origin.

Trace Engineering is developed within the LAB as an investigative practice composed of capabilities for tracing operations, locating decisions, comparing expected models with execution and producing verifiable explanations.

HORA.city serves as the LAB's Founding Reference Case 001 and remains an active internal investigation.

The LAB's operating principle is:

**Follow the flow. Understand the system.**

Software System Investigation is the primary field in which the Payload Journey LAB positions its work.

## 6. Core Investigative Orientation

### Payload Tracing

Payload tracing is the practical orientation of following an operation through the representations and boundaries it crosses during execution.

It supports questions such as:

* Where did this value come from?
* Where was this decision made?
* Which representation changed?
* Which layer held authority?
* Where did expected and observed behaviour diverge?

Payload tracing should not be presented as synonymous with distributed tracing, logging or observability as a whole.

## 7. Canonical Methods and Concepts

### Payload Journey

**Status:** Canonical within Payload Journey LAB

Payload Journey follows an operation through the representations, layers, interpretations, decisions, states and effects that compose its execution.

---

### USMT — Universal System Modeling Template

**Status:** Canonical within Payload Journey LAB

USMT is a modelling instrument for making an expected system model explicit through states, events, transitions, rules, invariants, boundaries and verifiable conditions.

Its canonical meaning is internal to Payload Journey LAB and must not be described as an externally established industry standard unless future evidence supports such a claim.

---

### Reverse Payload Journey

**Status:** Canonical investigation method within Payload Journey LAB

Reverse Payload Journey begins with an observable anomaly and follows the associated payload backwards through the system in order to reconstruct its path and locate the first evidence-backed divergence.

Its current operational sequence is expressed through:

**Freeze → Map → Detect → Restore**

where applicable to the investigation.

---

### Operational Payload Path

**Status:** Canonical investigation artefact within Payload Journey LAB

Operational Payload Path represents the bounded path actually investigated for a payload or operation.

It must distinguish observed, inferred, expected and unknown segments.

---

### Track to Origin

**Status:** Canonical investigative mission within Payload Journey LAB

Track to Origin is the deliberate pursuit of the earliest evidence-supported point at which a relevant value, representation, decision or authority originates.

Origin must not be declared before evidence establishes it.

---

### Track Mode

**Status:** Investigative operating practice

Track Mode is the deliberate shift from modification-oriented behaviour to evidence-oriented investigation.

Its purpose is to reduce premature correction and keep attention on the observable phenomenon, payload, path and evidence.

---

### Trace Engineering

**Status:** Developing investigative practice

Trace Engineering is a developing investigative practice composed of capabilities for tracing operations, locating decisions, comparing expected models with execution and producing verifiable explanations.

Trace Engineering is developed within Payload Journey LAB.

It must not currently be presented as an externally standardized discipline, established profession or universally recognized engineering field.

---

### Trace Engineer

**Status:** Developing investigative function/profile

Trace Engineer describes a developing investigative function or profile applying Trace Engineering capabilities.

It is not currently presented by Payload Journey LAB as:

* an established profession;
* an official occupational category;
* a protected title;
* an industry certification;
* a universally recognized engineering role.

## 8. Payload Journey LAB Evidence Model

The Payload Journey LAB Evidence Model distinguishes six evidence levels so that conceptual, documentary, runtime, implementation, verification and external evidence are not conflated.

### Level 1 — Conceptual Evidence

Expected models, definitions, diagrams, pedagogical representations and conceptual structures.

Conceptual Evidence establishes what is proposed, expected or modelled.

It does not establish observed execution.

---

### Level 2 — Documentary Evidence

Repository records, investigation notes, case statements, authored documents and other documented assertions.

Documentary Evidence establishes that something has been recorded or stated.

It does not by itself establish runtime behaviour.

---

### Level 3 — Runtime Evidence

Observed execution artefacts such as traces, logs, checkpoint captures, payload snapshots, request/response captures or runtime state observations.

Runtime Evidence establishes observed behaviour within a bounded execution context.

---

### Level 4 — Implementation Evidence

Source code, configuration, commits, diffs or equivalent artefacts demonstrating an implementation state or implemented change.

Implementation Evidence does not by itself establish that the intended runtime outcome occurred.

---

### Level 5 — Verification Evidence

Replay, test, bounded reproduction or controlled execution demonstrating an observed outcome after implementation or restoration.

Verification Evidence establishes that a claimed result was verified within the defined investigation boundary.

---

### Level 6 — External or Independent Evidence

Evidence produced, reproduced, reviewed or confirmed outside the founding or internal investigation context.

External or Independent Evidence does not automatically imply scientific peer review.
